The user gave standing permission to freely (a) create new `docs/` study files and (b) edit existing ones — adding new information or modifying/updating existing content — without prompting for approval each time. This applies specifically to the study/summary docs written for them to review (see [[feedback_study_docs]]). The user reconfirmed this permission and its cross-session persistence.

**Why:** They value the study docs and don't want the back-and-forth of approving each doc edit; they'll review them on their own.

**How to apply:** When a non-trivial technique comes up and a `docs/` study note would help, just create or update it — then mention it afterward. Do NOT ask permission ("May I edit docs?") AND do NOT gate it behind an offer ("Want me to write this up?"); both add the friction the user explicitly asked to remove. The user should never have to say "yes" before a study note gets written. This is a docs-only exception; the broader [[feedback_explain_dont_edit]] default (explain before editing *code*) still stands for source files unless the change was explicitly requested.
